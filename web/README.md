# 🥟 딤섬 클리커 웹 컨피규레이터

브라우저에서 슬라이더로 케이스를 실시간 재설계하고 층별 STL을 바로 다운로드합니다.

## 실행

```bash
# 프로젝트 루트에서 (stl_files/ 를 읽어야 하므로 반드시 루트에서)
python3 -m http.server 8123
```

브라우저에서 <http://localhost:8123/web/> 접속.

## 기능

- **제품 선택**: 딤섬 클리커 / 투두 서포터 / **운동 모션 센서**. 운동 센서는 TW802040 650mAh(40×20×8), KY-035(15×19), 선택형 0.96" OLED에 맞춘 기본 47×31×33.9mm 적층형입니다. OLED를 켜면 뚜껑 위 보호 림에 25×27.05mm 기판이 들어가고 23.2×12.4mm 화면이 위로 보이며, 4가닥 배선은 뚜껑 슬롯을 통해 ESP32로 내려갑니다. KY-035와 OLED는 각각 끌 수 있으며 포켓·부품·배선표도 함께 바뀝니다. KY-035를 끄면 배터리와 자석이 중앙 정렬되고, OLED를 끄면 평평한 뚜껑과 29.7mm 전체 높이로 돌아갑니다. OLED와 MPU6050은 GPIO8/9 I2C 버스를 공유합니다.

  KY-035는 3V3/GND와 아날로그 출력(GPIO0 같은 ADC 핀)으로 연결합니다. 부팅 시 내장 자석만 있는 기준값을 평균내고, 외부 자석을 붙인 상태의 값을 별도로 학습한 뒤 두 값의 중간값에 히스테리시스와 50~100ms 디바운스를 적용하면 운동 시작/끝점 오검출을 줄일 수 있습니다. 외부 자석 극성에 따라 값이 증가하거나 감소할 수 있으므로 변화 방향도 함께 저장해야 합니다.

- **모양**: 둥근 네모 / **완전 원형(딤섬 찜기)** — 원형은 W가 지름이 되고(기본 Ø54, 배터리 대각선 46.3mm 때문에 하한) D·모서리는 비활성. 원형에서는 충전모듈이 항상 중앙(Y 고정)이고 동쪽 벽에 폭 18mm 플랫 USB 패드가 생김(my_designs/rounded.png 참조). OLED 안착면은 곡률에 맞춰 자동 계산됨
- **외곽 디자인**: 가로/세로/모서리 둥글기/벽 두께/결합 유격. 결합 유격(기본 0.08mm)을 줄일수록 층이 꽉 끼움
- **V형 결합부** (기본 켜짐): 층간 홈·턱을 58° 계단 단면으로 만들어 위층 밑면에 서포트가 필요 없음 + 조립 시 자가 정렬. 끄면 기존 사각 단면
- **설정 자동 저장**: 모든 값이 localStorage에 저장되어 리로드해도 유지, '설정 초기화' 버튼으로 기본값 복원
- **미세조절**: 각 슬라이더 좌우 −/+ 버튼으로 step 단위 정밀 조정
- **프리셋 import/export**: 전체 설정을 .json 파일로 저장/불러오기 (여러 디자인 파일 관리)
- **층 높이**: 1·2·3층 + 스위치 보스 높이/스탠드 매립 깊이
- **부품 배치**: ESP32 위치·회전, 충전모듈 Y(USB는 항상 동쪽 벽), OLED 종류(0.49" 15×16 / 0.96" 26×26)와 벽 선택(서쪽 기본 = USB 반대), 배선구멍 위치·방향(가로/세로 14×5 슬롯 — 배터리 +/− 두 가닥이 함께 통과)
- **0.96" OLED**: 표시영역 22.74×11.86에 맞는 큰 창 + 모서리 4홀(22×22mm)에 맞는 Ø1.8 위치결정 핀 4개가 포켓 안에 자동 생성. 모듈이 26mm로 커서 타워가 높아지므로 2·3층 높이 경고를 확인할 것
- **OLED 타워 결합**: OLED는 타워 뒤(내부)에서 통째로 밀어 넣음 — 뒷면 완전 개방(15.5×16.3), 앞은 벽+디스플레이 창이 잡아줌. OLED 소켓은 2층 높이와 무관하게 항상 21.2mm 타워로 서고, 2층 벽보다 높으면 3층 뚜껑에 타워 모양 노치가 자동으로 커팅되어 끼워짐(조립 키 역할). 덕분에 2층을 16mm까지 낮출 수 있음
- **분해 ⟷ 조립** 슬라이더 + 애니메이션, 부품 고스트 표시, 케이스 반투명(X-ray)
- **배선 시각화** ('배선 표시' 토글): 실제 핀 배치 기반 전선 가이드 — 배터리 +/− → (2층 배선구멍 경유) → 충전모듈 B+/B−, OUT+/OUT− → ESP32 5V/GND, ESP32 3V3/GND/GPIO8/GPIO9 → OLED VCC/GND/SDA/SCL, 스위치 2가닥 → GPIO/GND (극성 무관, 3층 상판 중앙 통로 경유, 기본 G3), 2×5 투톤 LED → G7 빨강 / G6 초록 / 공통 캐소드 GND, 부저 + → G2. 기본 핀맵은 펌웨어 배선도(`wiring.html`)와 동일.
- **GPIO 핀 우클릭 변경**: 스위치·SDA·SCL 세 전선 모두 **우클릭하면 GPIO 선택 메뉴**가 뜨고, 고른 핀의 실제 위치로 전선이 이동. ESP32-C3는 I2C도 소프트웨어 핀이라 SDA/SCL도 자유 배정. 다른 전선이 쓰는 핀은 회색으로 비활성화되어 충돌 방지. 기본 스위치=G3(2개 모드 두 번째=G4), SDA=G8, SCL=G9, LED 빨강=G7, LED 초록=G6, 부저=G2 색상: 빨강 +, 검정 −, 초록 SDA, 주황 SCL, 보라 GPIO. 핀 라벨 스프라이트 포함, 분해 뷰를 따라감
- **측면 텍스처 (Weave 1·2·3 · Wood 1)**: 버튼 하나로 케이스 **바깥 옆면에만** 무늬를 새김. **케이스 외곽선(원통/둥근 네모) 위에 있는 면에만** 들어감 — OLED 타워·커버, 플랫 USB 패드, 결합 턱/홈처럼 외곽선에서 벗어난 면과 위·아래 면, 포켓 안쪽 벽은 매끈하게 남아서 층 결합·부품 끼움이 그대로 유지되고, 무늬는 **안쪽으로만** 파내므로 바깥 치수도 커지지 않음. 깊이·무늬 크기·디테일(mm/삼각형) 조절 가능. 무늬를 고르면 그 이미지에 맞는 무늬 크기·디테일이 자동으로 들어감 — 이미지 한 장 안의 반복 횟수가 달라서(Weave1 8회 / Weave2 6회 / Weave3 12회 / Wood1 29회) 같은 값을 쓰면 Weave3·Wood1 은 무늬 한 칸이 1mm 아래로 잘아져 뭉개짐. Wood 1 은 흑백 2치 나뭇결이라 결이 가로로 케이스를 감아 돎(tile 36 / 디테일 0.4) 무늬가 켜져 있으면 슬라이더를 드래그하는 동안에는 형상만 빠르게 갱신하고, 손을 떼면 CSG를 다시 돌리지 않고 무늬만 다시 입힘
- **조립 간섭 자동 검사**: 리빌드마다 층간 교집합 부피를 계산해 하단에 "조립 간섭 없음 ✓" 표시
- **STL 내보내기**: 층별 다운로드, 3층은 출력용 뒤집기 옵션 (크롬이 연속 다운로드를 차단하면 주소창의 다운로드 아이콘에서 허용)
- 배터리/부품이 안 들어가는 조합이면 하단에 경고 표시

## 구현

- CSG 엔진: **manifold WASM** (`vendor/manifold.wasm`) — 파이썬 생성기(`generate_dimsum_clicker.py`)와 동일 엔진이라 출력 STL이 항상 watertight
- 3층 스위치 자리는 `stl_files/keyboard_switch_stand.stl` 실물 메시를 3.5% 팽창시켜 그대로 boolean 절삭 → 스탠드가 보스에 자연스럽게 매립
- USB 구멍도 `stl_files/usb_c_hole.stl` 실물 형상 사용 (얇은 벽에 맞게 나팔부 60% 압축)
- 모든 라이브러리는 `vendor/`에 로컬 포함 — 오프라인 동작
- 측면 텍스처는 `texture.js` — 꼭짓점 용접 → 옆면 마스크(법선이 거의 수평 + XY 반직선으로 바깥 실루엣만 선별 + 호출부가 준 `opt.skip`: app.js 는 둥근 사각형 부호거리로 "외곽선에서 0.35mm 이내"인 면만 통과시킨다) → red-green 적응 세분화 → 트라이플래너 UV 로 높이맵 샘플 → 수평 법선 방향 변위. 높이맵은 최소/최대가 아니라 2%/98% 지점으로 오토레벨해서 JPEG 잡티가 대비를 잡아먹지 않게 함. 마스크 경계 꼭짓점은 고정이라 watertight 이 유지됨. [CNCKitchen/stlTexturizer](https://github.com/CNCKitchen/stlTexturizer) 의 파이프라인을 참고했고, `textures/` 의 weave 3장 + wood 1장은 해당 저장소(AGPL-3.0)에서 가져온 displacement map
